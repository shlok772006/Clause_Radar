# Phase 2 — CONTEXT.md: Grounding and Refusal

## Phase Goal
Ask a question → verified answer with "Show me" citation, or an honest refusal screen. Build the core grounding verifier, prompt injection defense, Gemini structured Q&A, and background P1 field extraction.

---

## Locked Decisions (From PRD & AGENTS.md)

1. **Stack & Model Discipline:**
   - Server-side only Gemini SDK (`@google/generative-ai`) with `GEMINI_API_KEY` from `.env.local`.
   - `temperature: 0` for all extraction, Q&A, and verification prompts.
   - Model target: `gemini-2.0-flash` (or `gemini-2.5-flash`) for low latency (~1s), low token cost, and strict schema compliance.
   - `responseMimeType: "application/json"` with explicit `responseSchema`.
   - Input format: ID-tagged clauses fenced with untrusted data delimiters (`[c_001 | p.1 | 1.1 Heading]`).

2. **The Grounding Verifier (`lib/verify.ts` — pure, tested):**
   - **Check 1 (Existence):** Cited `clauseId` must exist in document.
   - **Check 2 (Quote Fidelity):** `quote` must be a verbatim substring in the cited clause (after normalizing whitespace and case).
   - **Check 3 (Number Containment):** Every number, duration, or currency amount in the claim text must appear in the cited clause (allowing digit/word equivalence e.g. "60" ≈ "sixty").
   - **Check 4 (Confidence Floor):** Confidence < 0.55 downgraded or discarded.
   - **Check 5 (Aggregate Refusal):** If all claims are discarded, envelope becomes `status: "insufficient_evidence"`.

3. **Prompt Injection Defense:**
   - Explicit delimiters instructing the model that document text is untrusted data, never instructions.
   - 20-line wordlist scanner (`ignore previous`, `system prompt`, `disregard the above`, etc.) flagging suspicious contract text as a finding with severity `info`.

## Discussed & Confirmed Decisions

### 1. Model Choice
- Use `gemini-2.0-flash` (with fallback to `gemini-1.5-flash` if configured) for fast, deterministic, schema-constrained generation.

### 2. Ask Tab Experience
- Starter Question Chips: Display 4 quick one-click chips on empty state:
  - *"What is my notice period?"*
  - *"Is there an employment bond or penalty?"*
  - *"What are the non-compete and moonlighting restrictions?"*
  - *"Who owns inventions and intellectual property?"*
- Input bar: Text input with keyboard submission (`Enter`) and loading indicator showing step states.

### 3. ClaimCard vs. RefusalCard
- **`ClaimCard`:** Renders plain language claim text with verified `quote` pill, `p. {page}` badge, confidence indicator, and a "Show me" button that triggers `DocumentPane.highlightClause(clauseId)`.
- **`RefusalCard`:** The designed "I don't know" state.
  - Explains clearly: *"This agreement does not state an answer to your question."*
  - **Interactive Nearest Clauses:** Renders chips for the 3 closest clauses identified; clicking one highlights it in the `DocumentPane` with an explanation banner.
  - **Questions for HR/Lawyer:** Displays specific clarification questions generated by the model.

### 4. P1 Field Extraction
- Implement `lib/extract.ts` in Phase 2 for P1 extraction (20 core employment agreement fields).
- Run extraction in background or during ingest to populate `session.fields` in the in-memory store so verified fields are ready for Phase 3 risk rules.
